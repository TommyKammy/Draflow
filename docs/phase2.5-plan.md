# Phase 2.5 実装計画

起点は PR #10 マージ後の `main`（`b14a5da`）。Phase 2 で完成した「作成 → 実行 → 入出力確認 → 編集 → 再実行」の流れを、複雑な図の整理、式の入力支援、過去の実行の調査へ広げる。対象は **Tidy Up、グループ、スティッキーノート、実行一覧・履歴・リプレイ、コマンドパレット、式オートコンプリート**。本番 Webhook・cron、資格情報、サーバー保存などは従来どおり Phase 3 以降で扱う。[Phase 2 の提供範囲](phase2-plan.md)・[全体設計のキャンバス・式エディタ・実行一覧](design/draflow-design.md)

## 実装順

1マイルストーンを1 PR の目安とする。最初に既存の座標変更だけで Tidy Up を完成させ、次に付箋で表示専用データの保存・Undo を確立してから、ノードを束ねるグループへ進む。パレットには完成した操作を登録する。式補完は NDV 内で独立して検証できる。最後に、実行記録の保持契約を確定してから、その記録を読むリプレイを実装する。

### P1　Tidy Up

選択ノード、選択が空なら全ノードを16単位のグリッド上に層状配置する。隣接リストを一度構築し、分岐・合流を左から右へ配置する。閉路は強連結成分としてまとめ、独立した成分は間隔を空ける。同順位は文書内の順序で決め、全ノード対の距離探索を避ける。確定は既存の複数座標の `move` 編集1回で行う。[編集コマンド](../packages/element/src/store/edit.ts)

**受け入れ条件**

- 分岐・合流・孤立ノード・閉路の fixture で停止し、カードが重ならない。2回目は座標が変わらず Undo 履歴も増えない。部分選択では対象外を固定し、接続の両端・ポート・スロットを維持する。
- ブラウザで整列 → Undo → Redo → 保存・再読み込みを行い、全座標を比較する。整列後の Execute step で上流 mock HTTP の呼び出し回数が増えない。
- 200ノード／500エッジでクリックから配置反映までを測り、同じ図で既存の移動・パン・ズーム予算を通す。

### P2　スティッキーノートと表示データの保存

本文・位置・寸法・色を持つ付箋を追加する。本文はプレーンテキスト、色は限定したパレットとする。付箋と次のグループには、既存の任意 JSON 欄 `Workflow.meta` にエディタ専用の名前空間と版を設ける案を採る。実行エンジンに渡すノードや接続は増えない。作成・編集・移動・削除を既存の履歴と自動保存に通す。[文書形式](../packages/core/src/types.ts)・[シリアライズ](../packages/core/src/serialize.ts)

**受け入れ条件**

- 日本語・改行・HTML風の文字列を含む付箋を作成し、色・位置・寸法を変更できる。保存・再読み込みで表示が一致し、タグは文字として表示される。削除を Undo すると同じ ID と内容に戻る。
- 従来の `draflow/v1` 文書を読み込める。付箋を編集してもホスト独自の `meta` を保持する。未知のエディタデータ版はそのまま往復保存でき、その領域の編集を無効にする。
- 付箋だけを編集しても実行結果・ピン・上流キャッシュを保持する。閲覧専用では付箋を読める。

### P3　グループと折りたたみ

選択ノードをラベル付き矩形でまとめる。初版は1ノードにつき1グループ、グループは1階層。所属は安定したノード ID で保存する。折りたたみ時は境界をまたぐ接続だけをグループ外周に表示し、元の接続を保持する。グループの移動はメンバー座標を含む1編集として確定する。

**受け入れ条件**

- If の False 出力から Merge の第2入力に至る図で、一部をグループ化 → 移動 → 折りたたみ → 展開する。外部との接続・元のスロット・実行結果が一致する。グループ解除後もノードと配線が残る。
- 折りたたんだメンバーが Tab 移動や矩形選択の対象から外れ、展開をキーボードで操作できる。Tidy Up ではグループを一塊として扱い、メンバーの相対位置を保つ。
- メンバー削除と Undo、グループ移動の Undo、保存・再読み込みで所属と座標を比較する。削除・複製・貼り付け後に元文書や消失ノードへの所属参照が残らない。

### P4　コマンドパレット

エディタ内のボタンと Ctrl/Cmd+K で検索を開く。最初の対象はノード追加、フィット、整列、グループ化、付箋追加、実行・停止。コマンド ID、日英ラベル、実行可否、既存操作への呼び出しを小さな一覧に持ち、検索は部分一致から始める。ノード追加を選んだら既存の Node Creator を開く。

**受け入れ条件**

- 日本語・英語それぞれで検索し、矢印と Enter で実行、Escape で閉じて元のフォーカスに戻れる。狭い画面ではボタンとタップだけで同じ操作ができる。
- 選択なし・readonly・実行中の各状態でツールバーと同じ可否になる。2台のエディタを同じページに置き、操作した方だけが反応する。ホスト側の入力欄、NDV のモーダル、日本語変換中のキーを横取りしない。

### P5　式オートコンプリート

式欄のカーソル位置から、現在の入力フィールド、祖先ノード名、対応する拡張関数を候補にする。入力は NDV で選んだ runIndex・ポート・item を使い、祖先の値は既存の由来追跡に従う。プロパティ名のエスケープと評価可能な関数名は既存実装と共有する。候補は要求された階層だけを列挙し、最初の表示を最大20件とする。キー入力のたびに全実行データを走査しない。[マッピング](../packages/element/src/details/mapping.ts)・[拡張関数](../packages/core/src/expression/functions.ts)

**受け入れ条件**

- Filter を通過した2件目を選び、引用符を含む祖先名と空白を含む数値キーを補完する。プレビューと Set の出力で値・型が一致する。式中の前後の文字列は保持され、候補のキャンセルでは入力が変わらない。
- 対応型の関数候補を挿入して評価できる。入力なし・存在しないパス・祖先が特定できない場合にも入力を続けられる。IME 確定の Enter で候補を誤挿入しない。キーボードとタッチの双方を Chromium で検証する。
- 1,000キーを持つ入力で候補生成時間と表示件数を記録する。候補を閉じている状態の式評価は既存の 0.1 ms 基準を満たす。

### P6　実行履歴の記録と一覧

実行履歴はホストが有効にした場合に記録する。`WorkflowStore` と独立した任意の `ExecutionStore` を追加し、初版の同梱実装は上限付きメモリストアとする。保存先を提供するホスト向けに、追記、文書別のサマリー一覧、ID 指定の詳細取得、削除・保持上限の契約を公開する。実行開始時の文書スナップショットと実行 ID を結び、終了時に結果を確定する。一覧は現在の文書を新しい順に表示し、状態で絞り込める。[保存 API の設計案](design/draflow-design.md)・[現在の実行ログ](../packages/element/src/execution-log.ts)

**受け入れ条件**

- 全体・部分実行について成功・エラー・停止を区別し、実行 ID ごとに1件表示する。部分実行は対象と範囲を記録し、今回通ったタスクと再利用したタスクを区別する。文書 A の書き込みが文書 B に切り替えた後で終わっても、B の一覧や実行表示が変わらない。
- 一覧取得では入出力本体をロードしない。初版のメモリ上限案はストア全体で直近20件、詳細の合計4 MiB（シリアライズ時の UTF-8 バイト数）。件数・容量超過で古い記録から解放する。1件で上限を超える場合はサマリーだけを保持し、詳細を省いた旨を表示する。容量の境界、削除、ストア失敗時にも実行結果を表示できることをテストする。
- 未設定のホストでは履歴用の複製・直列化・保存を行わない。メモリ版はページ再読み込みで終了し、永続ストアを注入した fixture では再読み込み後も取得できる。既存の Clear execution は現在の結果とキャッシュを消去し、履歴削除は別操作とする。

### P7　実行リプレイとエディタへのコピー

初版のリプレイは、記録時の文書とタスク列を読み取り専用で開き、実行順に前後へ移動して当時の入出力を調べる操作とする。閲覧中のネットワーク呼び出しは0回。再編集したい場合は「エディタへコピー」で当時の文書を新しい文書 ID として開く。元の作業への復帰方法と文書 ID の管理は埋め込み例にも示す。

**受け入れ条件**

- mock HTTP → Filter → Set の実行後、元の図を編集してから過去の実行を開く。当時の名前・配線と、選択したタスクの runIndex・ポート・item・エラーが記録どおりに見える。前後移動・開き直しでも mock HTTP の呼び出し回数が増えない。
- 中断・失敗で未実行のノードや詳細省略の記録を判別できる。履歴 A の遅い詳細取得が、後から選んだ履歴 B や通常の編集画面を上書きしない。
- コピー後に編集・実行・保存し、元の文書と過去の記録が変化しないことを比較する。過去のタスクがコピー先の部分実行キャッシュに混入しない。readonly のホストでは履歴の閲覧だけが可能。

## 各 PR の合流条件

- **依存とサイズ** — 外部ランタイム依存は0。グラフ配置、検索、補完、履歴表示は既存の TypeScript とブラウザ API で実装する。各 PR で `pnpm size` の element・デモそれぞれの前後差を記録する。M8 記録値は **23.3 / 49.9 KB gzip**、既存の上限は **120 / 250 KB**。大きく増えた場合は追加機能ごとに内訳を確認する。[サイズ計測](../scripts/size-report.mjs)
- **描画と評価** — 同じ本番ビルド・固定 Chromium・1280 × 800・DPR 1 で比較する。50ノード初回と反復描画の p95 は100 ms 未満。200ノード／500エッジのパン・ズーム・移動は各100フレームで中央値18 ms 未満、p95 は34 ms 未満（目標約16.7 ms）。P3 では付箋と折りたたみグループを加えた同規模の図でも同じ操作を測る。数値参照・短いテンプレートは初回コンパイルを分け、温まった評価の平均が各0.1 ms 未満。[M8 の測定条件と実績](implementation.md#m8-埋め込みと最終計測)
- **回帰と公開契約** — `pnpm typecheck`、`pnpm test`、`pnpm build`、`pnpm test:browser`、`pnpm size`、`pnpm bench:canvas`、`pnpm bench:expression` を通す。公開 API を増やす PR は既存ホストと新 API の双方を strict / NodeNext 利用例で検査する。新しい UI は日英表示、360px 幅、キーボード、フォーカス復帰、readonly をブラウザで確認する。[埋め込み手順](embedding.md)
- **Phase 2.5 の完了** — 空のキャンバスから Manual → Set → If を作成し、パレットで整列、グループ化・付箋追加、式補完、実行記録、履歴閲覧、コピー先での再実行までを公開エントリのデモで通す。保存・再読み込み後の図、分岐結果、元文書とコピーの独立性を照合する。
